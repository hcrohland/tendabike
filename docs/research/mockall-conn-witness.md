# `mockall` as a `FakeConn` witness: what it can and cannot generate

**Origin.** Grilling session on the claim "axum tests should use mocks and the
mockall crate instead of `FakeConn`" (2026-10-17). The claim was declined for
the current seam; this document records the verified findings so the question
is never re-litigated from scratch.

**Question.** Can the hand-rolled `FakeConn` type witness (~490 lines,
`tb_axum::test_support`) be generated by `mockall`'s `mock!` — and if not,
exactly what blocks it?

**Bottom line.** `mock!` **can** put many traits on one type — including
`#[async_trait]` traits, by putting `#[async_trait]` on each impl block inside
the `mock!` invocation. The common assumption that "mockall generates one type
per trait" is therefore **wrong for `mock!`** (it is true only for
`#[automock]`). But the current seam blocks a generated `Conn` witness in
three ways, one of them structural: (1) a generic method with a where-clause
(`UsageStore::update<U>` → E0310); (2) a reference nested in an `Option`
(`stravauser_update_token(…, Option<&String>)` → E0637) — unfixable from the
`mock!` side, fixable by owning the parameter; (3) **method-name collisions**
across the store traits (`get` ×4, `create` ×3, `update` ×3, `delete` ×4 →
E0592) — mockall's expectations are one `expect_<name>` per mock type, so no
`mock!` configuration can combine traits that share method names. A four-item
recipe (§3) makes the witness generatable; it is a seam-wide API change. If
ADR-0006 / spec #525 lands, all of this is moot; while #525 is under
scrutiny, the recipe remains the viable mockall route.

---

## 0. Starting state (verified on `main` at `0c799353`)

- `FakeConn` is a unit struct with ~490 lines: eleven trait impls (the nine
  `Store` sub-traits, `StravaDataStore`, `Txn`) plus two method-free markers
  (`Store`, `StravaStore`); every method is `unimplemented!()` (never reached
  — `FakeSource::begin` fails fast with a `DatabaseFailure`).
- The seam: `TxnSource::Conn: StravaStore + Txn`; `Txn: Store`; `Store` is a
  method-free marker over the nine sub-traits. Every method-carrying trait is
  `#[async_trait]`.
- `mockall` is not a dependency anywhere in the workspace; the established
  pattern is hand-rolled doubles (`FakeConn`, `LiveConn`, `MemStore`,
  `TestStravaStore`).

## 1. Verified `mock!` capabilities (scratch-crate matrix)

Rust 1.99, `mockall` 0.15, `async-trait` 0.1.92. Each row compiled and tested
in isolation.

| Shape | Result |
| --- | --- |
| Multiple sync traits on one type, one `mock!` block | ✅ |
| Multiple **native** `async fn` traits on one type | ✅ |
| `#[async_trait]` traits, plain `mock!` block (`async fn` inside) | ❌ E0195 — `mock!` desugars `async fn` natively; the generated impl lacks the `+ 'async_trait` bound the macro puts on the boxed future |
| `#[async_trait]` traits, **`#[async_trait]` on each impl block inside `mock!`** | ✅ — the attribute passes through to the generated impl, which `async_trait` then desugars correctly. This is the trick that makes the rest of this document possible |
| `#[automock]` + `#[async_trait]` | ✅ per mockall's docs (attribute must precede `#[async_trait]`; canonical import) — but `#[automock]` generates **one type per trait**, so it cannot produce the single type `TxnSource::Conn` requires |
| Method-free marker impls inside `mock!` (`impl Store for Conn {}`) | ✅ |
| Consuming-`self` methods (`async fn commit(self)`) | ✅ |

## 2. The real seam against `mock!`

All of `FakeConn`'s impl blocks were mechanically converted to a single
`mock!` block (129 non-blank signature lines) and compiled against the actual
`tb_domain`/`tb_strava`/`tb_exec` crates. Three error classes remain:

1. **E0310 ×3 — `UsageStore::update<U: Borrow<Usage> + Sync>`.** The macro
   mangles where-clauses on generic methods. The seam's other generic,
   `StravaDataStore::request_json<T: DeserializeOwned>`, passes fine — inline
   bounds are OK, where-clauses are what break.
2. **E0592 ×4 — duplicate `expect_get` / `expect_create` / `expect_update` /
   `expect_delete`.** The colliding methods, by owner:

   | Name | Defined on |
   | --- | --- |
   | `get` | `UserStore`, `ServiceStore`, `ServicePlanStore`, `UsageStore` |
   | `create` | `UserStore`, `ServiceStore`, `ServicePlanStore` |
   | `update` | `UserStore`, `ServiceStore`, `UsageStore` |
   | `delete` | `ServiceStore`, `ServicePlanStore`, `UsageStore`, `AttachmentStore` |

   This is **structural**: mockall's expectation API is one `expect_<name>`
   per mock type, flat — not namespaced per trait. No attribute, lifetime, or
   configuration change removes it; only renaming the methods does.
3. **E0637 + E0106 — `Option<&String>` in
   `StravaDataStore::stravauser_update_token`.** A reference *nested in a
   composite type* needs a named lifetime in the generated code. The trigger
   is the nesting, not the `String`: `Option<&str>` fails identically, while
   top-level `&str` parameters are fine (several exist in the seam and pass).
   In-`mock!` fixes, all verified to fail: a named lifetime on the method
   (E0623), and `for<'a> mock! { … }` — the compiler's own suggestion, which
   is a syntax error (`for<'a>` cannot prefix a macro invocation at item
   position). The seam-side fix — `Option<String>`, owned — compiles cleanly.

## 3. The four-item recipe (makes a single `mock!` `Conn` generatable)

1. **Write the block with `#[async_trait]` on each impl** — a writing style,
   no code change (§1).
2. **De-genericize `UsageStore::update`** to take `&[Usage]`. Kills E0310.
   Call-site impact is one method: only `Usage::update` uses the `Borrow`
   indirection (`&[&self]` → `&[self]`; `self` is already owned, so no clone);
   the other three `update_vec` callers pass `&Vec<Usage>` unchanged; the two
   adapters drop `.borrow()`, and the in-memory adapter drops a clone.
3. **`stravauser_update_token` takes `Option<String>`.** Kills E0637. Impact:
   the passthrough signature on `StravaUser::update_token`, one
   `.map(RefreshToken::secret)` call site becoming
   `.map(|t| t.secret().to_string())` (one token-string clone per Strava
   upsert), the two adapter bodies, one test.
4. **Rename the 14 colliding methods** to the seam's existing
   `<entity>_<operation>` convention. Kills E0592. Proposed mapping:

   | Trait | Now | Proposed |
   | --- | --- | --- |
   | `UserStore` | `get`, `create`, `update` | `user_get`, `user_create`, `user_update` |
   | `ServiceStore` | `get`, `create`, `update`, `delete` | `service_get`, `service_create`, `service_update`, `service_delete` |
   | `ServicePlanStore` | `get`, `create`, `delete` | `serviceplan_get`, `serviceplan_create`, `serviceplan_delete` |
   | `UsageStore` | `get`, `update`, `delete` | `usage_get`, `usages_update`, `usage_delete` |
   | `AttachmentStore` | `delete` | `attachment_delete` |

   Already-prefixed methods (`user_delete`, `plan_update`, `usages_delete`,
   `delete_all`, `services_delete`, …) stay. Impact: the seam interface, both
   adapters, the domain call sites, and the seam suite — the store-seam
   contract (both adapters in lockstep, Postgres behavior the source of
   truth, CI-gated) applies in full.

Result: `FakeConn`'s ~490 lines become one `mock!` block of ~130 signature
lines; `FakeSource` is unchanged. `mockall` becomes a dev-dependency of
`tb_axum` only.

## 4. Relationship to ADR-0006 / spec #525

- ADR-0006 (under review as of 2026-10-17) makes `tb_strava`/`tb_exec`
  generic over a `Domain` trait; the consumer test doubles drop the ~78
  `Store` sub-trait methods for a ~17-method minimal surface (15
  `StravaStore` + 2 no-op `Txn`), all names prefixed and collision-free. Its
  executable spec is #525 (open). The implementation branch
  `feature/generic-domain` was **stopped as of 2026-10-17 while the ADR and
  spec are under scrutiny**.
- **If #525 lands:** the recipe is moot — no colliding surface, no boilerplate,
  no mockall needed.
- **If #525 is rejected or changed:** the recipe (§3) is the viable mockall
  route; the status quo (hand-rolled `FakeConn`) remains the third option at
  zero cost.
- The `FakeConn` doc comment (added in #547) was corrected to state the
  accurate blocker — the name collisions, not "one type per trait" — and to
  point here.

## 5. What this does not change

- The decision to keep the hand-rolled `FakeConn` on `main` stands.
- `LiveConn`/`LiveSource` — the delegating fixture that drives the real
  executor loop — is untouched by every option above; it is thin delegation,
  not boilerplate.
- No ADR was added for the mockall question itself: it is cheap to reverse,
  and this document carries the rationale at the right altitude.
